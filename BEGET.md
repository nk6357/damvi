# DAMVI на Beget: заявки на office@damvi.ru

Нужен обычный платный виртуальный хостинг Beget с PHP 8.2+ и mbstring.
Node.js и cURL для отправки формы не требуются. Почта отправляется через PHP `mail()` и почтовую службу хостинга, без SMTP-пароля, API-ключей и доступа сайта к чтению ящика.

## Установка

1. Создайте сайт, привяжите damvi.ru, выберите PHP 8.2+ с mbstring. Включите HTTPS и перенаправление HTTP → HTTPS в панели Beget.
2. Создайте и проверьте ящик **office@damvi.ru** в нужном почтовом сервисе. Если почта обслуживается Beget, проверьте MX и доступ через веб-почту. Для Apple Mail подключайте ящик по официальной инструкции Beget: это отдельная настройка клиента, сайту пароль не передаётся.
3. Выполните `npm run build`. Загрузите **содержимое dist/beget/public_html/** в public_html, включая скрытый `.htaccess`, `_pages` и `api/contact-lib.php`. Не загружайте весь репозиторий, private, tests или seo.
4. Рядом с public_html создайте каталог private с правами 700. Скопируйте туда contact.example.php под именем contact.php; права файла 600. PHP должен иметь право создавать служебные файлы в private. Права 777 не нужны.
5. В закрытом конфиге задайте точные `origins`: `https://damvi.ru` и при необходимости `https://www.damvi.ru`, без завершающего слеша. Не используйте `*`.
6. На сервере сгенерируйте секрет лимитера: `php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'`. Вставьте результат в `rate_secret` закрытого конфига. Это случайный ключ для хеширования IP, не пароль почты. Не публикуйте его в Git или чате.
7. Убедитесь, что исходящая отправка через `mail()` разрешена на тарифе. Получатель, From и envelope sender жёстко заданы как office@damvi.ru. Для них не используются поля посетителя.
8. Отправьте тестовую заявку с реального домена и проверьте получение письма в Beget и Apple Mail. Проверяйте также папку «Спам» и заголовки письма. PHP подтверждает принятие почтовой службой, а не гарантированную доставку во входящие.

```
site/
  private/                    # 700
    contact.php               # 600, origins и rate_secret
    mail-rate.json            # 600, создаётся автоматически, нет текста заявок
    mail-rate.json.lock       # 600, блокировка параллельных запросов
  public_html/
    .htaccess
    index.html
    app.js
    seo.js
    service-search-content.js
    other-services.js
    legal-documents.js
    styles.css
    assets/
    _pages/
    robots.txt
    sitemap.xml
    404.html
    api/
      contact.php
      contact-lib.php
```

Старые private/telegram.php и contact-rate.json больше не используются формой. После успешного перехода удалите ненужный конфиг с сервера; если токен больше не используется нигде, отзовите его в BotFather. Не копируйте старые секреты в новый релиз.

## Письмо

Тема — «Заявка с сайта 🔥». Жирный заголовок находится внутри HTML-письма: тему письма сделать жирной средствами сайта нельзя, её отображает почтовый клиент.
Письмо multipart/alternative содержит UTF-8 text/plain и text/html. В HTML телефон имеет ссылку вида `tel:+79111234567`; поддержка вызова зависит от устройства и установленного приложения. Все три поля и подтверждение согласия включены в письмо. Пользовательский HTML экранируется.

## Лимиты

— С одного фактического IP можно выполнить две успешные отправки подряд.
— Вторая успешная отправка запускает полный запрет на 600 секунд. Запрещённые повторы не продлевают ожидание. Если вторая отправка не сделана за 10 минут, запись о первой истекает.
— После ожидания снова доступны две отправки. Третья до истечения срока возвращает HTTP 429 и Retry-After.
— Резервирование и вызов почты защищены одной блокировкой. При ошибке транспорта резерв отменяется: неудачная отправка не расходует персональную или общую почтовую квоту. Успех — принятие письма почтовой службой, а не гарантия доставки во входящие. Частые неудачные запросы ограничивает отдельный входной лимитер.
— Дополнительные общие ограничения: 20 успешных отправок в минуту и 100 в час на весь сайт. Они могут увеличить ожидание при общей нагрузке.
— Счётчики защищены flock и атомарной заменой JSON. Повреждённое состояние блокирует отправку, а не обнуляет защиту молча.
— Клиенты одной офисной сети могут иметь общий IP. После запуска проверьте, что REMOTE_ADDR на Beget соответствует реальному посетителю. Не начинайте доверять X-Forwarded-For без подтверждённой схемы доверенного прокси.

## Проверки перед публичным запуском

— Прямые адреса страниц и обновление работают; canonical — damvi.ru.
— /api/contact.php при GET: 405; без закрытого конфига: 503; неизвестный API: 404.
— /private/contact.php, исходники конфигов и резервные копии недоступны из веба.
— Две тестовые заявки приняты; третья даёт 429. Не обнуляйте рабочие лимиты ради обхода защиты.
— Проверьте SPF, DKIM и DMARC по настройкам именно используемого почтового маршрута. DKIM для PHP mail() на Beget имеет отдельные условия; не считайте подпись автоматически настроенной из-за создания ящика. Не добавляйте вторую SPF-запись и не включайте жёсткий DMARC без проверки источников отправки.
— На сайте по-прежнему проекты политики и согласия. Теперь обработчик отправляет почту, но утверждение инфраструктуры, сроков хранения/удаления и документов остаётся отдельным шагом. Сам перевод на mail() не означает юридическую готовность.
— Не забывайте удалять отработанные заявки из почты, корзины и резервных копий по утверждённому порядку. Автоматическое удаление писем этот обработчик не выполняет: он не имеет доступа к ящику.

## Локальная проверка

`npm run build:local`, затем `npm run dev` — PHP-просмотр на 127.0.0.1:4174. Уже запущенный сервер на 4173 также использует тот же обработчик. Без private/contact.php форма честно сообщает, что отправка недоступна. На Mac mail() может отсутствовать как настроенный транспорт: не ожидайте реальной доставки без почтовой службы.

GitHub Pages не исполняет PHP. Там форма показывает уведомление о тестовой версии и office@damvi.ru; заявки не уходят через Telegram и не изображают успешную доставку. Старый Node-просмотр также не отправляет письма и возвращает 503 для POST формы.

Тесты без отправки реальных писем: `python3 tests/check-contact.py`. Они создают временный PHP-сервер и подменяют только его почтовую программу локальным перехватчиком. Тестовые переключатели в production-обработчик не добавлены.

Сборки и проверки: `npm run build:local`, `npm run build`, `node scripts/build-pages.mjs`, `node scripts/check-seo.mjs`, `node scripts/check-navigation.mjs`, `npm run check:search`.
Пакет с инструкцией и пустым примером конфига: `npm run package:beget`.

## Дополнительная защита сайта

Включены CSP, защитные заголовки и запреты доступа к служебным файлам. HSTS выдаётся только по HTTPS на сутки, без preload и includeSubDomains. Проверьте применение .htaccess и заголовков на реальном домене. GitHub Pages получает CSP через meta, но не HTTP frame-ancestors.
В private дополнительно появляются request-rate.json и request-rate.json.lock для лимита входящих запросов. Не публикуйте их и не сбрасывайте при обновлении релиза.
Веб-сайт не нуждается в микрофоне, камере, геолокации, USB и Payment Request: они отключены Permissions-Policy. Это не запрещает системный звонок по tel: или внешнюю ссылку Telegram.
Сборка очищает только свой целевой каталог внутри dist. Ручную папку с исходниками, секретами и резервными копиями там хранить нельзя.
Для сетевой защиты от DDoS нужен отдельный внешний уровень/настройки провайдера. Подключение без поломки почты и SEO: DDOS-BEGET.txt. Фактические изменения: SITE-SECURITY.txt.
