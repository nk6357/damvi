# Установка DAMVI на Beget

Подготовлен вариант для обычного виртуального хостинга: HTML/CSS/JS и PHP 8.2+ с cURL и mbstring. Node.js на хостинге не нужен. Файлы дизайна и тексты остаются в public/.

## Размещение

1. Создайте сайт и подключите домен в панели Beget. Выберите актуальную PHP 8.2 или новее и включите HTTPS с перенаправлением HTTP → HTTPS в панели.
2. Скопируйте **содержимое public/** в **папку public_html** сайта, включая скрытый `.htaccess`. Не загружайте весь репозиторий в public_html.
3. Рядом с public_html создайте папку private с правами 700. Скопируйте туда telegram.example.php под именем telegram.php, права файла 600. PHP должен иметь доступ к записи в private для файла ограничений частоты. Не используйте права 777.

Структура на сервере:

```text
site/
  private/
    telegram.php
  public_html/
    .htaccess
    index.html
    app.js
    other-services.js
    styles.css
    assets/
    api/contact.php
```

В private/telegram.php заполните bot_token, числовой chat_id получателя и origins: точные HTTPS-адреса сайта, без завершающего слеша. Например https://damvi.ru и https://www.damvi.ru. Не добавляйте произвольные домены или `*`.

## Подключение Telegram

Токен от BotFather означает, что бот уже создан. Найдите его в /mybots у официального @BotFather, откройте и нажмите «Старт». Без этого бот не сможет написать в личный чат.

Получить свой числовой ID можно локальным инструментом Telegram API getUpdates после сообщения боту. Токен вводите скрыто в локальном терминале или непосредственно в закрытом конфиге Beget; не вставляйте его в адресную строку браузера, исходники сайта, переписку или Git. Не пересылайте getUpdates сторонним сервисам: ответ содержит сообщения и идентификаторы. Альтернатива — использовать уже известный собственный числовой Telegram ID. @nk6357 не заменяет числовой ID личного чата.

Для этого сайта используйте отдельного бота. Не подключайте его как бизнес-бота к личному аккаунту, не выдавайте ему административные права и не передавайте пароль, SMS-код или Telegram-сессию. Боту достаточно отправлять сообщения в заданный личный чат.

После заполнения конфига отправьте одну тестовую заявку с сайта. Успех показывается только после подтверждения sendMessage от Telegram. Проверяйте не только уведомление на сайте, но и фактическое получение заявки.

## Что защищено

- Токен и получатель находятся за пределами публичной папки и не попадают в JS или HTML.
- Получатель и HTTPS-адрес API фиксированы сервером; посетитель не может изменить их полями формы.
- Нет исполнения команд, SQL-запросов, загрузки файлов или интерпретации HTML из заявки. В Telegram отправляется обычный текст с отключённым предпросмотром ссылок.
- Проверяются Origin, тип запроса, типы и длины всех полей. Установлены лимиты: одна попытка в минуту, пять в час с IP и сто в час суммарно. IP хранится как HMAC, без текста заявки.
- Лимиты обновляются под блокировкой файла; ошибки не раскрывают токен или ответы Telegram. Используется проверка TLS-сертификата и таймаут.
- Есть скрытая ловушка для простых ботов. Origin и ловушка не заменяют CAPTCHA против целевых атак; CAPTCHA можно добавить отдельно при появлении спама.

Нулевой риск обещать нельзя. Компрометация токена позволит управлять этим ботом, но токен обычного отдельного бота не является паролем или сессией личного аккаунта. При утечке перевыпустите токен в BotFather. Не открывайте ссылки из неизвестных заявок автоматически.

## Проверка перед публикацией

- Главная, /projects, /services/chatbots и остальные страницы открываются напрямую и после обновления.
- /api/contact.php при GET возвращает 405 JSON, при отсутствующем конфиге POST возвращает 503, а не сообщение об успешной доставке.
- /private/telegram.php недоступен через веб, исходники и архивы с секретами не лежат в public_html.
- Укажите настоящий текст политики конфиденциальности: сейчас на сайте сохранена существующая заглушка. Опишите передачу заявок в Telegram.
- Реальная доставка ещё требует заполнения bot_token, chat_id и origins на Beget. Без них обработчик безопасно возвращает ошибку.

## Локальная проверка

`npm run dev` или `npm run dev:beget` — сайт на http://127.0.0.1:4174 с реальным PHP-обработчиком. `npm run dev:node` — старый Node-просмотр; PHP он не исполняет.

Документация: https://beget.com/ru/kb/faq/hosting/php и https://core.telegram.org/bots/api#sendmessage.
