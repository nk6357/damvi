DAMVI — аудит GEO / AIO / AEO
Дата: 23 ноября 2026 года
Область проверки: текущий репозиторий, 3 статические сборки, локальный HTTP-сервер.
Это не подтверждение индексации damvi.ru или цитирования в AI-системах.

1. Исходное состояние

Рабочая копия до задания была чистой. Исходные сборки и проверки SEO и навигации проходили.
26 маршрутов: главная, проекты, каталог других услуг, 17 отдельных услуг,
3 задачи бизнеса, 3 правовые страницы. Дополнительно формируется страница 404.

Исходный снимок: before.json; итоговый: after.json в этой же директории.
Для каждого маршрута и окружения сохранены Title, Description, H1, canonical,
robots, Open Graph, JSON-LD, ссылки, ожидаемый статус, включение в sitemap,
объём текста и SHA-256 готового видимого HTML. Сохранены правила Apache,
алиасы, размер и SHA-256 основных ресурсов. Статусы в JSON — ожидаемые,
не результаты обращения к production-серверу.

2. Что уже было настроено

— Статическая генерация полноценного HTML: одна и та же система шаблонов
  используется для сборки и клиентской навигации.
— Уникальные Title и Description, один H1 на каждой странице.
— Canonical на https://damvi.ru; адреса услуг отдельные и стабильные.
— WebSite, WebPage/CollectionPage, Service, BreadcrumbList и Brand.
— У каждой услуги 4 видимых раскрывающихся ответа. Текст находится в HTML
  до раскрытия details: отдельный AJAX-запрос для его получения не нужен.
— В каждой услуге есть обычные ссылки на смежные услуги.
— 3 страницы задач бизнеса ведут на релевантные услуги.
— Production robots разрешает обход публичных страниц, исключает /api/ и /_pages/.
— Production sitemap содержит 24 страницы: privacy и consent пока исключены.
— Локальная и Pages-сборки: noindex, follow, пустой sitemap.
— Правовые черновики privacy и consent сохраняют noindex даже в production.
— Старый /services/support перенаправляется на /services/seo-blog.
— Неизвестная страница получает специальную 404-страницу с noindex.
— Из релиза исключены исследовательская семантика, private, .env и скрипты сборки.

3. Что изменено

3.1. Существующая разметка уточнена без новых фактов и типов.
— Brand на главной и в услугах получил единый @id https://damvi.ru/#brand.
  Это идентификатор сущности, отдельная страница /#brand не требуется.
— Service связан с описывающей его страницей через mainEntityOfPage.
— Уже существующие BreadcrumbList получили @id, а WebPage — ссылку breadcrumb.
— Существующие свойства сохранены. Не добавлены Organization, LocalBusiness,
  FAQPage, рейтинги, отзывы, адреса, филиалы, ФИО или новые коммерческие обещания.
Польза: однозначные связи уже описанных сущностей, а не «особая AI-разметка».
Это не гарантирует цитирование, позиции или расширенное отображение.

3.2. Добавлена офлайн-проверка scripts/check-search-readiness.mjs.
— Проверяет все 26 маршрутов и 404 в production, local и Pages.
— Проверяет готовый HTML, вопросы услуг, ссылки с якорями, sitemap и noindex.
— Проверяет уникальность верхнеуровневых @id и связи Service/WebPage/breadcrumb.
— Проверяет отсутствие внутренних каталогов в корне сборки.
— Режим --compare сравнивает с исходным снимком: обычные метаданные, ссылки,
  видимый HTML, robots и sitemap должны совпадать; изменения JSON-LD — только
  добавочные, без удаления или замены существующих значений.
— CSS, app.js, тексты услуг, юридические документы и другие зафиксированные
  ресурсы при сравнении должны оставаться неизменными; seo.js проверяется
  отдельно через значения метаданных и JSON-LD, поскольку именно он изменён.
— Проверка включена в workflow Pages, вместе с проверкой навигации.

Команды:
  npm run build:local
  npm run build
  node scripts/build-pages.mjs
  node scripts/check-seo.mjs
  node scripts/check-navigation.mjs
  npm run check:search
  node scripts/check-search-readiness.mjs --compare seo/geo-aio/before.json
  git diff --check

Сравнение с before.json предназначено для этой задачи. При будущей согласованной
редактуре контента снимок нужно обновлять осознанно. CI запускает текущие проверки,
но не запрещает навсегда менять согласованные тексты сравнением со старым снимком.

4. Что сохранено

Побайтово совпадает видимый HTML всех страниц во всех трёх сборках.
Не изменены дизайн, CSS, шрифты, адаптация, app.js, тексты услуг, цены, сроки,
гарантии, форма, доставка в Telegram, возврат на прежнее место и юридические тексты.
Совпадают Title, Description, H1, canonical, Open Graph, внутренние ссылки,
robots, состав sitemap, маршруты и правила перенаправлений.
Исследовательские списки ключей не опубликованы. Удалённые блоки не восстановлены.
Новых зависимостей, внешних запросов, трекеров, виджетов и анимаций нет.

5. Проверка локального сервера

Проверены GET-запросы из браузера, без отправки заявок:
— / и /services/chatbots: 200, готовый H1 и noindex в исходном HTML;
— /services/support: переход на /services/seo-blog, конечная страница 200;
  код начального 301 подтверждён настройкой PHP, а не измерением первого ответа;
— несуществующая страница: HTTP 404, H1 и noindex;
— неизвестный API-адрес: HTTP 404.

Предсуществующее отличие dev-сервера от релизной сборки:
на localhost /robots.txt берётся из public/ (Allow: /), а /sitemap.xml отвечает 404.
Сгенерированные dist/local/robots.txt и sitemap.xml корректны, но dev-router
не обслуживает эти два файла из dist/local. Это не изменение этого задания.
Все локальные HTML имеют noindex. Dev-router не является production-конфигурацией.
Маршрутизация не менялась по ограничению задания; проверять production-файлы
robots/sitemap нужно из готового пакета и затем на Beget.

Браузерная проверка в Chromium: все 26 страниц на ширинах 320, 390, 768, 1440 px.
Использованы iframe соответствующей ширины, ожидание шрифтов и кадров отрисовки.
Не обнаружено горизонтального переполнения документа, заголовков, абзацев,
списков, описаний характеристик, полей и кнопок. Это не тест реальных iOS-устройств
и не полная оценка визуального качества. CSS и видимый HTML при этом не изменены.
Форма не отправлялась: её код неизменен, реальная доставка не проверялась.

6. Ограничения и реальные направления дальнейшей работы

— В портфолио есть ссылки и краткие описания Insol и «Кинкали», но нет оформленных
  кейсов с подтверждёнными задачами, датами и измеримыми результатами.
— Для услуг общий бюджет и ограничения описаны, но точный состав минимального
  пакета, критерии приёмки и отдельные расходы требуют подтверждения исполнителя.
  Нельзя изобрести эти условия при технической оптимизации.
— Для SEO-блога не зафиксировано число публикаций в месяц; его нельзя придумывать.
— Некоторые формулировки о результатах SEO и блога звучат уверенно; предложить
  уточнения можно после согласования, но в этой работе они не переписаны.
— На странице проектов нет прямых ссылок на соответствующую услугу. Это возможное
  контентное улучшение, а не техническая ошибка. Новые видимые ссылки не добавлены.
— Главная метаинформация уже упоминает Пермь и работу по России. Она не расширена
  списками городов, опечатками или дополнительными ключевыми вариантами.
— Общий Allow в существующем robots не запрещает GPTBot. В этой работе доступ
  роботам обучения не расширялся и не изменялся. Поисковые и обучающие роботы
  имеют разные назначения; выбор запрета обучения — отдельное решение владельца.
— README содержит исторические сведения о шрифтах и запуске. Источник истины
  для сборки здесь — актуальные скрипты и конфигурация, а не старое описание.

Production-хостинг, доступ роботов через защиту Beget, HTTPS, фактическая индексация,
настройки панелей вебмастеров и реальные AI-цитирования в этой задаче не проверены.
Новых настроек в аккаунтах и на хостинге не выполнялось.

7. Официальные основания решений (проверены 23.11.2026)

Google, AI features:
https://developers.google.com/search/docs/appearance/ai-features
Официальная рекомендация: доступный текст, полезные внутренние ссылки,
соответствие разметки видимому содержимому. Специальные AI-файлы и новая
«AI-схема» для появления в AI Overviews/AI Mode не требуются. Поэтому llms.txt,
особые метатеги и скрытые ответы не добавлены. Это не обещает показ сайта.

Google, правила структурированных данных:
https://developers.google.com/search/docs/appearance/structured-data/sd-policies
Требование для соответствующих функций Google: разметка не должна вводить
в заблуждение и противоречить содержимому. Правильная разметка не гарантирует
расширенное отображение. Новые сведения об исполнителе не изобретались.

Schema.org — определения добавленных связей:
https://schema.org/mainEntityOfPage
https://schema.org/breadcrumb
https://schema.org/Brand
Словарь описывает отношения сущностей; сам по себе не обещает эффект ранжирования.
Назначение устойчивых @id — наше инженерное решение по согласованности данных,
а не обязательное требование AI-платформ или отдельный фактор, доказанный для DAMVI.

Яндекс — источники ответов ИИ и обнаружение страниц:
https://yandex.ru/support/webmaster/ru/alice
https://yandex.ru/support/webmaster/ru/robot-workings/robot.html
ИИ использует результаты поиска; доступность и обнаружение страниц остаются
основой. Отдельные выдуманные требования для Алисы не внедрялись.

Bing — Webmaster Guidelines:
https://www.bing.com/webmasters/help/webmaster-guidelines-30fba23a
Проверены доступные официальные поисковые выдержки: ясные сигналы обхода,
отсутствие гарантий AI-цитирования, недопустимость манипуляций моделью.
Полная страница справки через текстовый веб-инструмент требует JavaScript.
Специальные настройки Bing на основе недоступных разделов не выдумывались.

OpenAI — назначение роботов:
https://developers.openai.com/api/docs/bots
OAI-SearchBot — поиск; GPTBot — возможное обучение; ChatGPT-User — действия
по запросу пользователя. Правила независимы. Allow не гарантирует цитирование.
Отдельные разрешающие секции не добавлены, поскольку общий доступ уже разрешён.
