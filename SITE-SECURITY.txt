DAMVI — усиление защиты сайта, 23 ноября 2026 года

Изменения применены в рабочем проекте и сборках, не на аккаунте Beget.
До этой задачи уже имелись незакоммиченные изменения почтовой формы; они сохранены и дополнены.

Реализовано:

1. CSP ограничивает выполнение скриптов и сетевые обращения своим origin; запрещены eval/inline JS, плагины, base и вложенные фреймы. HTTP frame-ancestors и X-Frame-Options запрещают встраивание чужим origin. Локальные JS-модули, шрифты и картинки разрешены.
В style-src оставлен unsafe-inline для совместимости текущих стилей и изменений размеров через DOM; это разрешение CSS, а не JavaScript. Удалять его без отдельной проверки дизайна нельзя.
Политика добавлена в HTTP на Beget и локальном просмотре и в meta готового HTML. На GitHub Pages meta работает, но frame-ancestors через meta не поддерживается; полноценную защиту от встраивания там не заявляем.

2. Добавлены nosniff, Referrer-Policy, Permissions-Policy; отключён устаревший X-XSS-Protection, убран X-Powered-By там, где это контролируется нашим сервером. HSTS на Apache задаётся только при HTTPS на 86400 секунд, без preload и includeSubDomains. Реальное наличие заголовков на Beget проверяется после публикации; обратный прокси может влиять на их выдачу.

3. Apache запрещает чтение скрытых служебных файлов (с исключением .well-known для сертификатов), private/исследовательских каталогов, архивов/бэкапов/дампов, примеров конфигов и посторонних PHP. Правила срабатывают до выдачи существующих файлов. Прямой доступ к _pages закрыт, внутреннее SEO-перенаправление продолжает работать.

4. LimitRequestBody=20000; запрещены POST вне почтового API и ненужные методы. Встроенный TRACE в Apache требует отдельного TraceEnable Off на уровне сервера, не полагается на RewriteRule. В локальном Apache-тесте эта серверная настройка включена явно; состояние Beget не утверждается.

5. Новая отдельная квота входа в API: до 20 запросов на IP за минутное окно, затем минута ожидания; 300/мин и 3000/час суммарно. Она срабатывает до JSON/полевой валидации для запросов с разрешённым Origin и JSON Content-Type. Быстрые запреты метода/Origin/типа/заявленного размера выполняются ещё раньше. Это не защита канала от DDoS.

6. Основной лимит отправки сохранён: 2 успешные отправки на IP, после второй 600 секунд ожидания; отказ почты откатывает резерв под той же блокировкой. Общие лимиты теперь скользящие: 20 за любые 60 секунд, 100 за любые 3600 секунд. Для входной квоты также используются скользящие общие окна. Старые общие счётчики при наличии консервативно преобразуются; не открывается дополнительная квота из-за обновления.
Лимит хранит только HMAC IP и временные счётчики вне public_html. Входной request-rate.json и почтовый mail-rate.json независимы. Ошибочные поля расходуют входную квоту, но не почтовую.

7. Релиз пересобирается в чистую папку внутри dist: старые случайные файлы в неё не переносятся. Сборка отклоняет выход за dist и symlink в цепочке каталога вывода. Публичные JS/CSS/API копируются по списку; из api только contact.php и contact-lib.php. В assets допускаются изображения, шрифты и LICENSE.txt, скрытые файлы и symlink запрещены. Исследовательские материалы, конфиги и тесты не публикуются.

8. Локальные Node/PHP-серверы также блокируют служебные пути. Node привязан к loopback, не доверяет Host для разбора URL, не отдаёт PHP и проверяет реальный путь файла внутри public. Это защита просмотра, не production-сервер для Beget.

Проверки:
— Три сборки, SEO 26 страниц, навигация, noindex preview.
— Изолированный PHP/MTA: инъекции, типы, Origin, неправильные запросы, лимиты, параллельная отправка, недоверие X-Forwarded-For, ошибки конфигурации и почты. Письма не отправлялись.
— Настоящий локальный Apache 2.4: HTTP-заголовки, закрытые canary-файлы даже при их наличии в public, ACME и внутренние SEO-rewrite. TLS и настройки Beget не проверялись этим тестом.
— В браузере CSP заблокировала контрольный inline-скрипт; форма активна, шрифты загружены, JSON-LD читается, переходы в задачи/услуги/правовые страницы/проекты работают.
— Сборка удаляет тестовый старый .env и PHP-бэкап, отклоняет небезопасный каталог вывода.

Команды:
node tests/check-build-security.mjs
python3 tests/check-contact.py
python3 tests/check-web-security.py
Последний тест требует локальный Apache 2.4 и путь к модулям (APACHE_MODULES). Никакие публичные серверы не атакуются.

Что НЕ сделано:
внешняя DDoS/WAF не подключена, DNS и тариф не изменены, платные услуги не заказаны; нет заявления о защите от любой атаки. Панель, резервные копии, права хостинга и настоящая доставка почты требуют проверки на Beget. Статическая сборка не защищает от заполнения сетевого канала. Следующий шаг описан в DDOS-BEGET.txt.
